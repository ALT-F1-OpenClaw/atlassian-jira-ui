### #63 — Sprint State Filter Dropdown

### #64 — Environment Ribbon on Login Page

- Now also appears on the login page so users know which environment before authenticating
- Uses `jiraSettings.app_env` from `/api/config`

### #33 — Per-User Jira Site Selection (ADR-019)
- Full-screen site picker shown after OAuth login when user has access to multiple Jira sites
- Displays site name, URL, avatar for each accessible site
- Selection persisted in `localStorage` per user — picker only shows once
- Backend endpoints already existed (`GET /auth/sites`, `POST /auth/select-site`)
- ADR-019 documents the architecture

### #35 — Rate Limiting & Abuse Protection (ADR-020)
- Tiered per-IP rate limiting using `slowapi`:
  - API reads: 60/min (default)
  - Auth endpoints: 10/min (login, callback, logout, site-switch)
  - Search: 30/min (JQL queries)
  - Mutations: 30/min (create/update/delete)
- All limits configurable via env vars (`RATE_LIMIT_API`, `RATE_LIMIT_AUTH`, `RATE_LIMIT_SEARCH`, `RATE_LIMIT_MUTATION`)
- Custom 429 JSON response with `Retry-After` header
- Applied to 18 mutation endpoints across issues, sprints, projects
- ADR-020 documents the architecture

### #36 — Multi-Tenant Data Isolation (ADR-021)
- **Token encryption at rest**: OAuth tokens encrypted with Fernet (AES-128-CBC), key derived from `APP_SECRET_KEY` via SHA-256
- **Session fingerprinting**: Sessions bound to `sha256(IP + User-Agent)`, rejected on mismatch
- **Settings lockdown**: `PATCH /api/settings` returns 403 in production mode
- **Cloud ID scoping**: Every API call uses session's own `cloud_id`, validated against accessible-resources
- Added `cryptography>=43.0.0` as explicit dependency
- ADR-021 documents all four layers

### #37 — Terms of Service Page
- Full ToS page with 11 sections: service description, account & auth, data handling, acceptable use, availability, liability, IP, termination, changes, governing law (Belgium), contact
- Accessible from sidebar (📜 icon), login page footer ("Terms" link), breadcrumbs
- Static component (no API needed), responsive, dark/light mode
- Includes disclaimer that a lawyer should review before public launch

## Decisions Made

1. **v1.0 requires 8 must-haves** — rate limiting, multi-tenant isolation, ToS, GDPR, cookie consent, production infra (Let's Encrypt), Redis sessions, app name
2. **Belgian law governs ToS** — ALT-F1 SRL is registered in Brussels
3. **App name cannot contain "Jira"** — registered trademark of Atlassian
4. **Fernet encryption for tokens** — key derived from APP_SECRET_KEY, key rotation invalidates all sessions
5. **Session fingerprinting trade-off accepted** — dynamic IP users may need to re-login
